# PKD Segmentation QC — end-to-end codebase audit

**Audit date:** 2026-07-31 · **branch:** `work` · **scope:** repository HEAD plus the
bundled ITK-SNAP reference archive. This is an engineering audit, not a clinical
validation or regulatory clearance. No ITK-SNAP code was copied.

## Executive assessment

The program is a compact PySide6 general-purpose medical-image segmentation editor. It supports both loading an existing segmentation (including external AI output) and creating a blank segmentation for manual work. AI QC is a major workflow, not the sole product purpose. Organ and cyst segmentations remain separate files edited one at a time. It canonicalizes NIfTI inputs
to RAS+, holds a contiguous `uint16` editable label array, presents three linked
pyqtgraph MPR panes and an optional PyVista/VTK surface, records voxel diffs for
undo/redo, periodically checkpoints the complete label array, computes voxel-count
volumes, and exports NIfTI. The core/UI separation and plane mapping are promising,
but the current product is **not ready for relied-upon clinical use**. Round 1A has resolved strict label validation, transactional edit rollback, and shared label protection; DICOM geometry and close/open recovery lifecycle remain unsafe and later milestones are still required.

## Method, repository state, and exclusions

`git status --short --branch` was clean (`## work`) before this audit. The original
`itksnap-master.zip` was retained byte-for-byte and extracted read-only for analysis
to `/tmp/pkdqc-itksnap-audit/itksnap-master` (1,394 archive entries, about 24 MiB).
No `AGENTS.md` was present under `/workspace` or its parent search scope.

Reviewed: all tracked human-authored `.py`, Markdown, requirements, batch, and
PyInstaller files; every test; the benchmark and preview; archive index, build/version
metadata, GPL, and representative ITK-SNAP framework/model/renderer/interaction/I/O
sources. Excluded from line-by-line project review: `.git/`; tracked and untracked
`__pycache__/*.pyc` (generated bytecode); the ZIP's 1,394 third-party/reference files
from the *project* manifest (representative source was separately inspected); caches,
virtual environments, build/dist outputs, compiled binaries, and vendored dependencies
(none otherwise present). Binary ZIP content was inspected by archive listing and
targeted extraction rather than treated as application source.

### Risks and missing requirements (not asserted as defects)

* Display flips are internally invertible, but no phantom/DICOM anatomical-marker test
  establishes radiological versus neurological left/right presentation. Add visible
  L/R/A/P/S/I markers derived from affine and validate with a known asymmetric phantom.
* NIfTI canonicalization changes voxel ordering intentionally; qform/sform codes, intent,
  units, descriptions, and label metadata are not preserved. Define an export contract.
* No real representative datasets are checked into a de-identified test corpus; there is
  no end-to-end clinical ground truth, accessibility, installer, signing, SBOM, or threat
  model validation.
* `SegmentationLayers` is not wired, so simultaneous organ/cyst/baseline comparison is a
  design stub rather than implemented capability.

## Strengths

* `Plane` centralizes extraction and exact inverse mapping, avoiding three divergent
  editing implementations.
* Voxel-diff commands make ordinary brush/lasso/fill edits compact and exact; the history
  is bounded on its undo side.
* NIfTI affine mismatch is rejected rather than silently overlaid, and export is atomic.
* 3D is optional and failures do not prevent the 2D editor from starting.
* The test suite covers all three plane mappings, anisotropic aspect, protected paint,
  affine mismatch, and undo/redo on small deterministic arrays.

## Test interpretation

The unit suite establishes mathematical behavior for small canonical arrays. It does not
prove DICOM geometry, left/right correctness, crash atomicity, UI input mapping through
Qt transforms, large-volume responsiveness, or save provenance. The offscreen preview
establishes that a synthetic case can construct/render widgets in this environment; it
does not simulate reviewer gestures or persistence workflows.
